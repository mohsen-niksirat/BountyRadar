# چک‌لیست پیش از گرفتن هر Bounty

قبل از نوشتن حتی یک خط کد، این ۹ چک را به ترتیب انجام بده. اگر یکی از «چک‌های قرمز» رد شد، همان‌جا رها کن.
زمان لازم: ۱۰–۱۵ دقیقه. اگر بیش از ۳۰ دقیقه صرف بررسی شد و جواب نگرفتی، یعنی خود bounty مشکل دارد.

---

## ۱) ایشو واقعاً باز است؟
```bash
curl -s https://api.github.com/repos/OWNER/REPO/issues/NUMBER \
  | grep -oE '"(state|comments|created_at|updated_at|locked)": ("[^"]*"|[0-9]+|true|false)'
```
- `state` باید `open` باشد. اگر `closed` بود → رها کن (پلتفرم‌ها برچسب را بعد از پرداخت هم پاک نمی‌کنند).
- تاریخ `created_at` را ببین: bounty‌های چند ساله معمولاً یعنی «کسی توانسته حلش کند، پس تو هم نمی‌توانی».

## ۲) کسی دیگر روی آن PR باز نکرده؟
```bash
curl -s -H "Accept: application/vnd.github+json" \
  https://api.github.com/repos/OWNER/REPO/issues/NUMBER/timeline?per_page=100 \
  | grep -oE '"https://github.com/OWNER/REPO/pull/[0-9]+"' | sort -u
```
- هر PR لینک‌شده = یک رقیب. **۰ = عالی، ۱ = سریع جلو بزن، ۲+ = برو سراغ bounty دیگر.**
- مسیر جایگزین: در گیت‌هاب بنویس `repo:OWNER/REPO NUMBER type:pr is:open`

## ۳) تعداد claim/رقیب روی خود پلتفرم چقدر است؟
- Algora: صفحهٔ `https://algora.io/OWNER/bounties` → ستون claims را ببین (بالای ۱۰ = شانس کم).
- Opire: صفحهٔ bounty (`app.opire.dev/issues/...`) → «solvers are trying | claimed».
- **قاعده:** خیلی از bountyهای باز «باقیمانده» هستند؛ عدد بزرگ = کسی برنده نشده، نه اینکه جای خالی است.

## ۴) مبلغ و منبع پول واقعی است؟
- مبلغ روی ایشو تیتر («$50») **مدرک نیست**؛ فقط صفحهٔ پلتفرم مدرک است.
- در Opire مجموع rewardها را ببین و اینکه وضعیت `Available` است یا `Paid`.
- اگر برچسب `💎 Bounty` / `:dollar: Funded on Issuehunt` دیدی ولی پلتفرم متناظر آن bounty را نشان نمی‌دهد → **پول وجود ندارد**.
- 🚩 علائم قطعی کلاهبرداری: مبلغ نجومی برای تسک بی‌معنی، مخزن تازه با صدها ایشوی قالب‌بندی‌شده، درخواست «اتصال کیف پول / امضای تراکنش».

## ۵) این مخزن PR بیرونی را merge می‌کند؟
```bash
curl -s "https://api.github.com/repos/OWNER/REPO/pulls?state=closed&per_page=20" \
  | grep -oE '"(merged_at|login)": ("[^"]*"|null)' | head -20
```
- باید چند `merged_at` غیر `null` از افراد غریبه (نه collaborator) ببینی.
- اگر همهٔ PRها `null` هستند یا فقط اعضای تیم merge می‌شوند → پروژه درِ بیرونی را بسته است؛ **کار نکن**.
- نقطهٔ مساعد: `accepts_external_pr` و سرعت پاسخ maintainer (median first response).

## ۶) معیار پذیرش مشخص است؟
- در ایشو دنبال این‌ها بگرد: رفتار مورد انتظار، معیار پذیرش، تست لازم، اینکه پرداخت کامل است یا جزئی، چه کسی merge می‌کند.
- اگر این‌ها نیست: **یک کامنت بگذار و قبل از کار جواب بگیر.** کار نکردن روی ایشوی مبهم ارزان‌تر از ساختن PR رد‌شده است.

## ۷) می‌توانی محلی تست/بیلد را اجرا کنی؟
```bash
git clone --depth 1 https://github.com/OWNER/REPO && cd REPO
cat CONTRIBUTING.md 2>/dev/null | head -40
ls package.json pnpm-lock.yaml yarn.lock .github/workflows 2>/dev/null
```
- `CONTRIBUTING.md` + فایل قفل پکیج + ورک‌فلوی CI را بخوان.
- بیلد/تست باید در ۱۵ دقیقه سبز شود. اگر نه، bounty گران‌تر از مبلغش است.
- قبل از هر تغییر، یک بار تست‌ها را روی شاخهٔ دست‌نخورده اجرا کن (برای baseline).

## ۸) پرداخت به کشور من ممکن است؟
- Opire از طریق پرداخت آنلاین (Stripe) تسویه می‌کند؛ Algora هم برای payout اطلاعات مالیاتی/1099 می‌خواهد.
- قبل از کار این را در تنظیمات حساب خودت چک کن: **کشور ایران تحریم است و احتمال مسدود بودن مسیر پرداخت وجود دارد.**
- اگر پرداخت به کشورت ممکن نیست: bounty را برای «سابقه/پرتفولیو» انجام بده، نه برای پول — و این را از قبل بدان، نه بعد از merge شدن PR.

## ۹) بودجهٔ زمانی و شرط خروج
- سقف زمان بگذار: bounty ≤ `$50` → حداکثر ۳ ساعت؛ `$50–150` → حداکثر ۸ ساعت؛ بیشتر → فقط بعد از ۵ bounty موفق.
- شرط توقف: اگر در نصف بودجه به PR قابل‌اجرا نرسیدی، ایشو را با یک کامنت مودبانه رها کن («هنوز روی این کار می‌کنم/کنار می‌کشم») تا سابقه‌ات خراب نشود.
- بعد از merge: PR را به title bounty لینک بده و روی Opire از داشبورد claim کن (یا با کامندهای OpireBot).

---

## قالب سریع تصمیم (۳ خط)
```
bounty: OWNER/REPO#NUMBER  | amount: $__.  | claims: __  | PRs open: __
repo: stars=__  pushed=__  merges outside PRs: yes/no  | build+test locally: yes/no
حکم: ادامه می‌دهم / رها می‌کنم   دلیل: ____________________
```

**قاعدهٔ طلایی:** ارزش انتظاری = (مبلغ ÷ شانس merge) ÷ ساعت کار.
bountyهای کوچکِ *تازه* (کمتر از ۲۴ ساعت، ۰–۲ claim) معمولاً از bountyهای بزرگِ *قدیمی* (۱۰۰+ claim) ارزش بیشتری دارند.
